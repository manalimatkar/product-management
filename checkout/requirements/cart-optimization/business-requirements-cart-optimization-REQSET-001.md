## 2. Business Context

### Problem or Opportunity

Shoppers using the cart need a safe way to remove items they no longer want, a way to apply a coupon code with clear feedback, and a way to return to browsing when the cart is empty -- all currently causing friction that contributes to cart abandonment.

### Desired Business Outcome

Reduce cart abandonment and improve the item-management experience, per the stated objective and success metrics (cart abandonment rate, time to checkout) in the source Design Handoff Bundle's `businessContext`.

### Users, Actors, and Affected Parties

| Actor ID | Actor, Role, or Affected Party | Need or Responsibility | Source Reference |
| --- | --- | --- | --- |
| `ACTOR-001` | Shopper (end user) | Manage cart contents and apply discounts before checkout | `checkout/analysis/cart-optimization/design-analysis-cart-optimization-DA-001.md` §3 |

## 3. Scope

### In Scope

- Removing an item from the cart, with confirmation before the removal takes effect, and updated totals afterward.
- Applying a coupon code, with distinct success and failure feedback.
- Communicating an empty cart and offering a path back to browsing.
- Desktop web only.

### Out of Scope

- Mobile experience -- no mobile frames exist in the source (`GAP-001`).
- Quantity editing (the "editing" state) -- no trigger or resulting behavior is established in the source (`GAP-002`, `DEC-003`).
- Any guest-vs-signed-in behavior difference -- not represented in the source (`DEC-004`).

## 5. Requirements

### Requirement `BR-001`: Confirm Before Removing an Item

- **Statement:** The product must require the shopper to confirm before an item is removed from the cart, for the shopper, so that accidental, irreversible loss of a cart item is prevented.
- **Actor or Beneficiary:** Shopper
- **Capability, Workflow, or Domain Area:** `CAP-002` Remove Item from Cart
- **Business Outcome:** Prevents accidental item loss
- **Classification:** `Explicit`
- **Confidence:** `High`
- **Evidence:** `checkout/analysis/cart-optimization/design-analysis-cart-optimization-DA-001.md` OBS-003, OBS-007
- **Business Rules:** `BRULE-001`
- **Assumptions:** `None`
- **Decisions:** `None`
- **Dependencies:** `None`
- **Related Downstream Items:** `STORY-001`

#### Acceptance Criteria

##### `AC-001`

```text
Given a cart with at least one item
When the shopper clicks Remove on an item
Then the product shows a confirmation prompt
And the item is not removed until the shopper confirms
```

##### Additional Cases

- **Validation:** `Not established`
- **Loading or In Progress:** `Not applicable`
- **Empty or No Result:** `Not applicable`
- **Success or Completion:** `See AC-002`
- **Error or Exception:** `Not established`
- **Permissions or Authority:** `Not applicable`
- **Recovery or Escalation:** `Shopper may cancel the confirmation, leaving the cart unchanged`

### Requirement `BR-002`: Update Cart on Confirmed Removal

- **Statement:** The product must remove the item from the cart and update the displayed totals, for the shopper, so that the cart accurately reflects their intent after removal.
- **Actor or Beneficiary:** Shopper
- **Capability, Workflow, or Domain Area:** `CAP-002` Remove Item from Cart
- **Business Outcome:** Accurate cart state after removal
- **Classification:** `Strongly Implied`
- **Confidence:** `High`
- **Evidence:** `checkout/analysis/cart-optimization/design-analysis-cart-optimization-DA-001.md` OBS-004
- **Business Rules:** `BRULE-001`
- **Assumptions:** `None`
- **Decisions:** `None`
- **Dependencies:** `DEP-001` (max cart size affects edge-case totals behavior only, not this core requirement)
- **Related Downstream Items:** `STORY-001`

#### Acceptance Criteria

##### `AC-002`

```text
Given the confirmation prompt is shown for an item
When the shopper clicks Confirm Remove
Then the item is removed from the cart
And the cart's displayed totals are updated to reflect the removal
```

##### Additional Cases

- **Validation:** `Not established`
- **Loading or In Progress:** `Not established (recalculation mechanism is a technical unknown, not resolved here)`
- **Empty or No Result:** `Removing the last item transitions to the empty-cart state (BR-004)`
- **Success or Completion:** `Item removed, totals updated`
- **Error or Exception:** `Not established`
- **Permissions or Authority:** `Not applicable`
- **Recovery or Escalation:** `Not established`

### Requirement `BR-003`: Validate and Apply Coupon Codes

- **Statement:** The product must validate a coupon code the shopper submits and give distinct visible feedback for success and failure, for the shopper, so that discount application is unambiguous.
- **Actor or Beneficiary:** Shopper
- **Capability, Workflow, or Domain Area:** `CAP-003` Apply Coupon Code
- **Business Outcome:** Unambiguous discount feedback, supporting conversion
- **Classification:** `Explicit`
- **Confidence:** `High`
- **Evidence:** `checkout/analysis/cart-optimization/design-analysis-cart-optimization-DA-001.md` OBS-005
- **Business Rules:** `BRULE-002`
- **Assumptions:** `None`
- **Decisions:** `DEC-002`
- **Dependencies:** `DEP-002`
- **Related Downstream Items:** `STORY-002`

#### Acceptance Criteria

##### `AC-003`

```text
Given the shopper has entered a coupon code
When the shopper clicks Apply and the code is valid
Then a confirmation is shown
And the discount is applied to the cart totals

Given the shopper has entered a coupon code
When the shopper clicks Apply and the code is invalid
Then an inline error is shown
And the coupon input keeps focus
```

##### Additional Cases

- **Validation:** `Coupon code is checked on submission; exact rules pending DEC-002`
- **Loading or In Progress:** `Not established`
- **Empty or No Result:** `Not applicable`
- **Success or Completion:** `Confirmation shown, discount applied`
- **Error or Exception:** `Inline error, input retains focus`
- **Permissions or Authority:** `Not applicable`
- **Recovery or Escalation:** `Shopper can correct and resubmit; input remains focused for that purpose`
