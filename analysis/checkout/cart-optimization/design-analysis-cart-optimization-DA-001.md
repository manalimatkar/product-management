## 2. Source Summary

### Purpose of the Source Material

The source material is a Design Handoff Bundle for a redesigned shopping cart, covering the empty-cart state, the cart-with-items state (including item removal and coupon application), and the flow from the product detail page into the cart. Per the bundle's `businessContext`, the stated objective is to reduce cart abandonment and improve the item-management experience.

## 6. User Journeys and Workflows

### Journey `JRN-001`: Remove an Item from the Cart

- **Actor:** Shopper
- **Goal:** Remove an item they no longer want to purchase
- **Preconditions:** Cart contains at least one item (`STATE-002`)
- **Expected Outcome:** Item is removed and totals reflect the change

| Step | User Action | Product Response | Resulting State | Evidence |
| --- | --- | --- | --- | --- |
| 1 | Click Remove on an item | Confirmation prompt shown | Awaiting confirmation | `OBS-003` |
| 2 | Click Confirm Remove | Item removed, totals updated | `STATE-002` (item removed) | `OBS-004` |

### Journey `JRN-002`: Apply a Coupon Code

- **Actor:** Shopper
- **Goal:** Reduce the cart total using a discount code
- **Preconditions:** Cart contains at least one item (`STATE-002`)
- **Expected Outcome:** Valid code reduces the total; invalid code is rejected with clear feedback

| Step | User Action | Product Response | Resulting State | Evidence |
| --- | --- | --- | --- | --- |
| 1 | Enter a code in the coupon input | None until submitted | `STATE-002`, unchanged | `SRC-001` |
| 2 | Click Apply | Success: confirmation shown, discount applied to totals. Failure: inline error shown, input keeps focus | `STATE-002`, totals updated (success) or unchanged (failure) | `OBS-005` |

### Requirement `BR-001`: Confirm Before Removing an Item

- **Statement:** The product must require the shopper to confirm before an item is removed from the cart.
- **Actor:** Shopper
- **Capability:** `CAP-002`
- **Business Outcome:** Prevents accidental, irreversible loss of a cart item
- **Evidence:** `OBS-003`, `OBS-007`
- **Classification:** Explicit
- **Confidence:** High
- **Business Rules:** `BRULE-001`
- **Assumptions:** None
- **Decisions:** None
- **Acceptance Criteria:** `AC-001`

### Requirement `BR-002`: Update Cart on Confirmed Removal

- **Statement:** When the shopper confirms removal, the product must remove the item from the cart and update the displayed totals.
- **Actor:** Shopper
- **Capability:** `CAP-002`
- **Business Outcome:** Cart accurately reflects the shopper's intent after removal
- **Evidence:** `OBS-004`
- **Classification:** Strongly Implied

- **Business Rules:** `BRULE-001`
- **Assumptions:** None
- **Decisions:** None
- **Acceptance Criteria:** `AC-002`

- **Statement:** The product must let the shopper submit a coupon code, validate it, and give distinct visible feedback for success (discount applied) and failure (inline error, input retains focus).
- **Actor:** Shopper
- **Capability:** `CAP-003`
- **Business Outcome:** Supports discount-driven conversion without ambiguous feedback
- **Evidence:** `OBS-005`

- **Actor:** Shopper
- **Capability:** `CAP-001`

- **Confidence:** High

## 10. Acceptance Criteria

### Criteria `AC-001` for `BR-001`

```text
Given a cart with at least one item
When the shopper clicks Remove on an item
Then the product shows a confirmation prompt
And the item is not removed until the shopper confirms
```

### Criteria `AC-002` for `BR-002`

```text
Given the confirmation prompt is shown for an item
When the shopper clicks Confirm Remove
Then the item is removed from the cart
And the cart's displayed totals are updated to reflect the removal
```

### Criteria `AC-003` for `BR-003`

```text
Given the shopper has entered a coupon code
When the shopper clicks Apply and the code is valid
Then a confirmation is shown
And the discount is applied to the cart totals

Given the shopper has entered a coupon code
When the shopper clicks Apply and the code is invalid
Then an inline error is shown
And the coupon input keeps focus
```

### Criteria `AC-004` for `BR-004`

```text
Given the cart contains no items
When the shopper views the cart
Then the product displays a message indicating the cart is empty
And the product offers a way to continue shopping
```

Additional cases to consider:

- **Validation:** Represented for coupon codes (`AC-003`); not represented for item removal (no invalid state shown for Remove).
- **Loading:** Not represented in source.
- **Empty:** Represented (`AC-004`).
- **Success:** Represented for removal (`AC-002`) and coupon (`AC-003`).
- **Error:** Represented for coupon (`AC-003`); not represented for removal.
- **Permissions:** Not represented in source.
- **Recovery:** Represented via the Cancel path (`PATH-001`); not written as a formal requirement since cancelling simply leaves state unchanged.
