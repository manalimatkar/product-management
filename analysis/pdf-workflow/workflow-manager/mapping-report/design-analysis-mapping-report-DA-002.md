## 2. Source Summary

### Purpose of the Source Material

The source is the Mapping Report screen of the Formwork workflow manager: a review surface for workflows created by uploading a PDF, where the system has already extracted a page/section/field structure from that PDF (with a per-item confidence score) and proposed a mapping from each extracted element onto a workflow target (a section, a static content block, a single field, a repeating field group, or a custom app component). The report's job is to let a user review that proposed mapping, see how confident the extraction was, correct anything wrong, and manually add or reorder structure the extraction didn't capture. Per the source's own scope note, this report only applies to the PDF-creation path -- manually-created workflows have no report (the editor already shows their structure), and an LLM-based creation path is explicitly named as a possible future reuse of this same component, not built now.

## 10. Acceptance Criteria

### Criteria `AC-001` for `BR-001`
```text
Given a workflow's Mapping Report is opened
When the page renders
Then five stat tiles are shown: Total, High, Medium, Low, and Average confidence
And each tile's top border is colored by its confidence band
```

### Criteria `AC-002` for `BR-002`
```text
Given a workflow with multiple pages, and at least one page with multiple sections
When the reviewer views the mapping
Then pages, sections, and fields are shown as a collapsible three-level hierarchy
And a page correctly shows more than one section when the source data has more than one
```

### Criteria `AC-003` for `BR-003`
```text
Given the reviewer has an active search term, a confidence filter, and a field row expanded for edit in Table view
When the reviewer switches to Card view
Then the same search term, filter, and expanded-edit state are still active
And no data is lost or reset by the view switch
```

### Criteria `AC-004` for `BR-004`
```text
Given a workflow with fields at multiple confidence levels across multiple sections and pages
When the reviewer selects the "Low" confidence filter
Then only fields below 50% confidence remain visible
And any Section with no remaining visible field is hidden
And any Page with no remaining visible Section is hidden
```

### Criteria `AC-005` for `BR-005`
```text
Given a field-group mapping with 3 sub-fields
When the reviewer views its Target Type tag
Then the tag reads "Field-List-3x" (or the equivalent compound label for its actual item count)

Given a field-kind row
When the reviewer looks for a remap option
Then only Field-type targets are offered, never a Section, Content, FieldGroup, or Custom target
```

### Criteria `AC-006` for `BR-006`
```text
Given a field-group mapping is opened for edit
Then the edit panel shows a Label input, a per-item field list (each with its own label, type, and remove control, plus "+ Add field"), and Min items/Max items inputs

Given a heading or description mapping is opened for edit
Then the edit panel shows a single Text textarea and nothing else
```

### Criteria `AC-007` for `BR-007`
```text
Given field row A is expanded for edit
When the reviewer clicks the pencil icon on field row B
Then row A collapses without saving
And row B expands with its own edit controls
```

### Criteria `AC-008` for `BR-008`
```text
Given a FieldGroup mapping with 2 sub-fields
When the reviewer clicks unlink
Then a confirmation dialog opens naming the 2 sub-fields that would be lost
And the mapping is removed only if the reviewer confirms
```
Note: this criterion assumes `GAP-002` resolves in favor of the "confirmation exists" reading (`OBS-011`) -- if resolved the other way, this criterion must be rewritten, not silently kept.

### Criteria `AC-009` for `BR-009`
```text
Given the reviewer clicks "+ Add page"
Then a new page is appended, numbered one higher than the current maximum page number
And it renders expanded, showing only a "+ Add section" prompt
And no confirmation dialog is shown
```

### Criteria `AC-010` for `BR-010`
```text
Given a page with zero or more existing sections
When the reviewer adds a section with a title and no description
Then the Add action is available only once the title is non-empty
And the new section appears grouped under that page exactly like an extracted section, at 100% confidence
```

### Criteria `AC-011` for `BR-011`
```text
Given a section is expanded
When the reviewer adds a field with a label and a type
Then the Add action is available only once the label is non-empty
And the new field appears immediately after that section's existing fields, with no page reload
```

### Criteria `AC-012` for `BR-012`
```text
Given a page with zero sections
Then a delete (trash) icon is shown next to its expand toggle

Given a page with at least one section
Then no delete icon is shown for that page
```

### Criteria `AC-013` for `BR-013`
```text
Given three fields in one section, in order A, B, C
When the reviewer clicks the down-reorder control on field A
Then the order becomes B, A, C
And fields not explicitly moved retain their natural relative order
```

### Criteria `AC-014` for `BR-014`
```text
Given a field's edit panel is open with unsaved changes
When the reviewer attempts to navigate away (switch rows, or leave the page)
Then a discard-confirmation dialog appears
And the navigation completes only if the reviewer confirms discarding
```
Note: same `GAP-002` caveat as `AC-008`.

### Criteria `AC-015` for `BR-015`
```text
Given a workflow created via the "Upload PDF" path
Then its Mapping Report is available and meaningful (confidence, source, kind all populated)

Given a workflow created via "Manually create"
Then no Mapping Report is shown for it
```

Additional cases to consider:
- **Validation:** Represented for "+ Add section"/"+ Add field" (Add disabled until required field filled) (`AC-010`, `AC-011`); not represented for the field-group Min/Max items inputs (no stated validation rule between them).
- **Loading:** Not represented in source -- how the report behaves while extraction/confidence data is still loading is not described.
- **Empty:** Represented for a workflow with zero mappings at all is not explicitly described (only "page/section with zero children" is) -- see `GAP-004`.
- **Success:** Represented for edit-save (toast, per `OBS-011`) and for add-page/section/field (immediate appearance).
- **Error:** Not represented -- no failure case is shown for save, add, delete, or reorder (e.g. a network failure mid-save).
- **Permissions:** Not represented -- see `DEC-006`.
- **Recovery:** Represented via Cancel (`PATH-001`) and, per the contested `OBS-011`, a discard-confirmation (`PATH-002`).
