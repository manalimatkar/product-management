## 2. Business Problem and Desired Outcome

### Problem or Opportunity
Workflows created from an uploaded PDF have their structure extracted automatically, with a confidence score per mapping. That extraction can misjudge, miss, or need correcting. Reviewers currently have no confidence-aware, correctable view of it.

### Desired Business Outcome
A reviewer can assess and correct a PDF-extraction's mapping quickly, without needing to understand how the extraction itself works.

## 3. Epic: `EPIC-002` -- Mapping Report Review and Correction

Lets a workflow manager user review a PDF-extraction's proposed mapping, understand how confident it was, correct what's wrong, and fill in what it missed.

### Story `STORY-001`: Review Extraction Confidence and Browse the Mapping

**As a** workflow manager user, **I can** see a confidence summary and browse the mapping as a Page → Section → Field hierarchy, **so that** I can judge how much review effort a workflow needs and navigate it structurally.

- **Traces to:** `BR-001`, `BR-002`
- **Independently valuable:** yes -- browsing and confidence review are useful before any correction is made.

#### Acceptance Criteria
```text
Given a workflow's Mapping Report is opened
When the page renders
Then five stat tiles are shown: Total, High, Medium, Low, and Average confidence
And the mapping is shown as a collapsible three-level Page/Section/Field hierarchy
And a page correctly shows more than one section when the data has more than one
```
- Additional cases: empty-workflow state not established -- see `DEC-004`.

### Story `STORY-002`: Filter, Search, and Switch Views

**As a** workflow manager user, **I can** search and filter mappings by confidence, and switch between Table and Card views without losing my place, **so that** I can focus on what needs review in whichever layout I prefer.

- **Traces to:** `BR-003`, `BR-004`
- **Independently valuable:** yes -- usable on its own regardless of whether anything is edited.

#### Acceptance Criteria
```text
Given a workflow with fields at multiple confidence levels
When the reviewer selects the "Low" confidence filter
Then only fields below 50% confidence remain visible, and empty Sections/Pages are hidden

Given the reviewer has an active search, filter, and an in-progress edit in Table view
When they switch to Card view
Then all of that state is preserved
```

### Story `STORY-003`: Correct a Mapped Field's Details

**As a** workflow manager user, **I can** edit a mapped field's label, type, or sub-structure using controls specific to what kind of element it is, **so that** I can fix what the extraction got wrong.

- **Traces to:** `BR-005`, `BR-006`, `BR-007`
- **Independently valuable:** yes -- the core correction capability.
- **⚠ Provisional -- `DEC-001` unresolved (backlog):** built on the working assumption that editing is an in-place expand panel, not a dropdown remap. The source document contradicts itself on this; if resolved the other way, this Story's acceptance criteria need rewriting, not just its implementation.

#### Acceptance Criteria
```text
Given a field-group mapping is opened for edit
Then the panel shows Label, an editable per-item field list, and Min/Max items inputs

Given field row A is expanded for edit
When the reviewer clicks the pencil icon on field row B
Then row A collapses without saving, and row B expands with Save/Cancel actions
```

### Story `STORY-004`: Unlink an Incorrect Mapping

**As a** workflow manager user, **I can** unlink a wrong mapping and be told what it costs before it's gone, **so that** I don't lose a multi-field mapping by accident.

- **Traces to:** `BR-008`
- **Independently valuable:** yes.
- **⚠ Provisional -- `DEC-002` unresolved (backlog):** built on the working assumption that unlink requires confirmation. The source contradicts itself on this too.

#### Acceptance Criteria
```text
Given a FieldGroup mapping with 2 sub-fields
When the reviewer clicks unlink
Then a confirmation dialog names the 2 sub-fields that would be lost
And the mapping is removed only if confirmed
```

### Story `STORY-005`: Manually Add Missing Structure

**As a** workflow manager user, **I can** add a page, section, or field the extraction missed, **so that** the workflow's structure is complete even where extraction fell short.

- **Traces to:** `BR-009`, `BR-010`, `BR-011`
- **Independently valuable:** yes.

#### Acceptance Criteria
```text
Given the reviewer clicks "+ Add page"
Then a new, empty, auto-numbered page appears, expanded, with no confirmation dialog

Given a page is expanded
When the reviewer adds a section (title required) and then a field (label required) to it
Then both appear immediately, grouped exactly like extracted structure
```

### Story `STORY-006`: Remove Empty Structure

**As a** workflow manager user, **I can** delete a page or section once it has no content, **so that** I can clean up without any risk of losing data.

- **Traces to:** `BR-012`
- **Independently valuable:** yes.

#### Acceptance Criteria
```text
Given a page with zero sections
Then a delete icon is available for it, with no confirmation dialog

Given a page with at least one section
Then no delete icon is shown
```

### Story `STORY-007`: Reorder Structure

**As a** workflow manager user, **I can** move a page, section, or field one position among its siblings, **so that** I can fix ordering mistakes without redoing the whole list.

- **Traces to:** `BR-013`
- **Independently valuable:** yes.

#### Acceptance Criteria
```text
Given three fields in one section, in order A, B, C
When the reviewer moves field A down one position
Then the order becomes B, A, C
```

### Story `STORY-008`: Get Warned Before Losing Unsaved Edits

**As a** workflow manager user, **I can** be warned before an in-progress edit is discarded, **so that** I don't silently lose correction work.

- **Traces to:** `BR-014`
- **Independently valuable:** yes, though it only matters in combination with `STORY-003`.
- **⚠ Provisional -- `DEC-002` unresolved (backlog):** same contradiction as `STORY-004`.

#### Acceptance Criteria
```text
Given a field's edit panel is open with unsaved changes
When the reviewer attempts to navigate away
Then a discard-confirmation dialog appears, and navigation proceeds only if confirmed
```

### Story `STORY-009`: See the Report Only for PDF-Created Workflows

**As a** workflow manager user, **I** only see a Mapping Report for workflows created via the PDF path, **so that** manually-created workflows aren't cluttered with an irrelevant review screen.

- **Traces to:** `BR-015`
- **Independently valuable:** yes -- a scope rule with directly observable behavior.

#### Acceptance Criteria
```text
Given a workflow created via "Upload PDF"
Then its Mapping Report is available

Given a workflow created via "Manually create"
Then no Mapping Report is shown for it
```

## 9. Scope

### In Scope
- Reviewing extraction confidence and browsing the mapping hierarchy (`STORY-001`).
- Searching, filtering, and switching views (`STORY-002`).
- Correcting a mapped field via kind-specific editing (`STORY-003`).
- Unlinking an incorrect mapping (`STORY-004`).
- Manually adding pages, sections, and fields (`STORY-005`).
- Removing empty structure (`STORY-006`).
- Reordering structure (`STORY-007`).
- Discard-confirmation on unsaved edits (`STORY-008`).
- Restricting the report to PDF-created workflows (`STORY-009`).

### Out of Scope
- LLM-based workflow creation (source explicitly defers it).
- Mobile/tablet layout (`DEC-005`).
- Org-level role/permission distinctions (`DEC-006`).
- Workflow Dashboard and Workflow Settings Dialog (same v2 drop, separate feature-slices per DESIGN-HANDOFF-BUNDLE-SPEC.md section 6.2, not covered by this PR).
