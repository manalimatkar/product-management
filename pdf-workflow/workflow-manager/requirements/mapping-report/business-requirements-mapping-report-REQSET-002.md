## 2. Business Context

### Problem or Opportunity

Workflows created from an uploaded PDF have their page/section/field structure extracted automatically, each mapping carrying a confidence score. That extraction is not perfect: it can misjudge what an element is, miss structure entirely, or need correcting. Reviewers currently have no confidence-aware, correctable view of that extraction.

### Desired Business Outcome

A reviewer can see how much of a PDF-extracted workflow's mapping needs attention, correct what's wrong (relabeling, retyping, or unlinking a mapping), and fill in structure the extraction missed -- without needing to understand the underlying extraction mechanism.

### Users, Actors, and Affected Parties

| Actor ID | Actor, Role, or Affected Party | Need or Responsibility | Source Reference |
| --- | --- | --- | --- |
| `ACTOR-001` | Workflow manager user (reviewer) | Review and correct a PDF-extraction's proposed field mapping before the workflow is used | `DA-002` section 3 |

## 3. Scope

### In Scope

- Viewing extraction confidence and browsing the Page → Section → Field mapping (`BR-001`, `BR-002`)
- Filtering, searching, and switching between Table and Card views (`BR-003`, `BR-004`)
- Correcting a mapped field's details via kind-specific controls (`BR-005`, `BR-006`, `BR-007`)
- Unlinking an incorrect mapping (`BR-008`)
- Manually adding a page, section, or field (`BR-009`, `BR-010`, `BR-011`)
- Deleting empty structure (`BR-012`)
- Reordering pages, sections, and fields (`BR-013`)
- Warning before an unsaved edit is lost (`BR-014`)
- Restricting the report to PDF-created workflows (`BR-015`)

- All technical implementation (extraction mechanism, reorder-list storage, save persistence -- `TECH-001`, `TECH-002`).
